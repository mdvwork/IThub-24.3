# Черновик описания Todo API для ревью в КТ6


Сервис хранит задачи с полями `id`, `name` и `isComplete`. Оператор иногда создаёт две задачи с одинаковым названием для разных случаев; различать их он должен по `id`. Другой сценарий — изменить только признак выполнения задачи, сохранив её название.

## Операции

| Запрос | Описание | Ответ |
|---|---|---|
| `POST /todoitems` | Создаёт задачу из `name` и `isComplete`. Если задача с таким `name` уже есть, повторное создание отклоняется. | При создании — `201 Created`, объект с новым `id` и заголовок `Location`. При совпадении `name` — `409 Conflict`. |
| `GET /todoitems` | Возвращает все задачи. | `200 OK`, массив задач. |
| `GET /todoitems/complete` | Возвращает только задачи с `isComplete: true`. | `200 OK`, массив задач. |
| `GET /todoitems/{id}` | Возвращает задачу по её `id`. | Для существующей задачи — `200 OK` и объект; для отсутствующей — `404 Not Found` без тела. |
| `PATCH /todoitems/{id}` | Изменяет только поля, переданные в JSON. Если передан один `isComplete`, `name` остаётся прежним. | Для существующей задачи — `204 No Content` без тела. |
| `PUT /todoitems/{id}` | Для смены только статуса достаточно передать `isComplete`; пропущенное поле `name` сохранит прежнее значение. | Для существующей задачи — `204 No Content` без тела. |
| `DELETE /todoitems/{id}` | Удаляет задачу. Повторный `DELETE` с тем же `id` также возвращает `204`, потому что удаление идемпотентно. | `204 No Content` без тела при первом и повторном запросе. |
