# «Медиаполка»: что должна делать программа

## Ситуация

Дежурный медиалаборатории выдаёт студентам микрофоны, штативы и свет. Программа должна показывать остаток и запоминать выдачи, чтобы оборудование не терялось в учёте. Она уже написана, но в учебной версии есть ошибки. Нужно разобраться, при каких действиях они проявляются, написать тесты и исправить логику.

Это текстовая программа на Python. Дежурный выбирает позицию и количество, затем может вернуть оборудование по ID выдачи. Базы, сайта, входа по паролю и сети нет. Данные хранятся в памяти до выхода.

## Требования версии 1.0

| ID | Правильное поведение |
| --- | --- |
| R1 | Начальное состояние: микрофоны — 3, штативы — 1, LED-свет — 0; выдач нет. Выдача/возврат одной позиции не меняет остатки других. Независимые экземпляры состояния не влияют друг на друга. |
| R2 | Количество приходит строкой; пробелы по краям удаляются. Разрешены целые количества 1, 2, 3 включительно. Пустая строка, текст, дробь, отрицательное число, 0 и число больше 3 отклоняются: `ok=False`, сообщение «Введите целое количество от 1 до 3». Всё состояние остаётся прежним, включая счётчик ID. Проверка R2 выполняется раньше R3. |
| R3 | Если допустимое по R2 количество больше доступного, операция отклоняется: `ok=False`, сообщение «Недостаточно оборудования». Всё состояние остаётся прежним. |
| R4 | Успешная выдача возвращает `ok=True`, сообщение «Выдано» и `loan_id`. Создаётся одна запись с ID, позицией, количеством и статусом `issued`; соответствующий остаток уменьшается. ID начинается с 1 и увеличивается на 1 для каждой успешной выдачи внутри одного экземпляра состояния. Отказ ID не расходует. |
| R5 | Возврат записи `issued` увеличивает остаток на всё выданное по ней количество, меняет статус на `returned`; новая запись не создаётся. Ответ: `ok=True`, «Возвращено». Частичного возврата нет. |
| R6 | Повторный возврат той же записи отклоняется: `ok=False`, «Уже возвращено»; всё состояние остаётся прежним. Неизвестный ID также отклоняется без изменений: `ok=False`, «Выдача не найдена». |

Правильность определяется этими требованиями. Исходный код показывает, что программа делает сейчас, и может противоречить им. Не меняйте требование под текущую реализацию.

## Как устроены данные

`new_state()` каждый раз создаёт новое независимое состояние:

```python
{
    "stock": {"mic": 3, "tripod": 1, "light": 0},
    "loans": [],
    "next_id": 1,
}
```

Коды позиций: `mic` — микрофон, `tripod` — штатив, `light` — LED-свет. Вызов `issue(state, "mic", "2")` пытается выдать два микрофона и меняет переданный `state`. Ответ — словарь с `ok` и `message`, при успехе ещё с `loan_id`.

Пример записи успешной выдачи: `{"id": 1, "item": "mic", "quantity": 2, "status": "issued"}`.

`return_loan(state, 1)` возвращает оборудование по ID 1. Операции работают с одним и тем же `state`: это позволяет проверить последовательность событий.

Не передавайте несуществующие коды позиций и объекты других типов: меню предлагает фиксированные позиции и передаёт количество строкой. В этой работе проверяем поведение по R1–R6 в описанном интерфейсе функций.

## Сброс

В каждом независимом тесте используйте новый `state = new_state()`. Внутри сценария «выдать → вернуть → вернуть снова» состояние должно сохраняться. В текстовом меню команда 3 сбрасывает все данные. ID может снова начаться с 1 после сброса — это новый экземпляр состояния.

## Чего не добавляем

Фамилии получателей, сроки, штрафы, бронь на дату, сохранение после выхода, параллельные пользователи, мобильная версия. Исправляйте нарушения заданных правил, не расширяйте продукт.
